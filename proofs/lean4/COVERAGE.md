## What the proofs establish

The new modules contain executable specifications and kernel-checked theorems.
`ProtocolTrace` proves induction over arbitrary finite histories, with rejected
operations leaving state unchanged. Each consumer must prove its own transition
preservation theorem; the invariant is not a state constructor field.

`AdaptiveQif` uses normalized rational probability kernels and observation-dependent
query strategies. `FieldRangeProofs` uses `ZMod 2130706433` with kernel-checked
primality. Mathlib and transitive revisions are locked in `lake-manifest.json`;
the top-level mathlib revision is `4bbdccd9c5f862bf90ff12f0a9e2c8be032b9a84`.
The Lean compiler remains 4.14.0.

The mandatory gate is `python3 scripts/check-lean.py`; it builds the root, tests
and executable, audits theorem kinds and transitive logical axioms, compares
reviewed theorem types, and records exact source hashes. No `sorry`, `admit`,
custom proof axiom, `native_decide` shortcut or assumed security conclusion is
an acceptable completion mechanism. Standard disclosed Lean logical principles
are permitted. `Test/ProtocolCoverageTest.lean` is imported by `Test.lean`.

## Audit method and evidence

Pass 1 checks compilation, theorem kinds, transitive axiom dependencies, reviewed
types, test imports and reproducibility. Adversarial gate tests must demonstrate
that a fake theorem, axiom, admitted proof or weakened type is rejected.

Pass 2 reads each objective against its definitions, hypotheses, operational
coverage and implementation call sites. It rejects assumed conclusions, inert
Boolean assertions, impossible premises, toy cryptography, vacuous languages,
single-step proofs advertised as arbitrary histories, and model/implementation
conflation. Counterexamples become regression tests and repair work.

Audit outcomes, subsequent fixes and elapsed-time checkpoints are recorded in
`docs/formal/lean4-coverage-ticket.md`. Incremental two-pass reviews do not
constitute full twenty-area sign-off; that final review remains incomplete.

## Reproduction

From `proofs/lean4`, run `lake exe cache get` on first setup to fetch the locked
mathematics dependencies and their compiled cache, then build with the pinned toolchain.
From the repository root:

```sh
python3 scripts/check-lean.py
python3 -m unittest discover -s scripts/tests -p test_lean_gate.py
python3 scripts/check-formal-correspondence.py
python3 scripts/check-protocol-correspondence.py
python3 scripts/extract-epoch-air.py
cargo test --locked -p enclave-zk-auditor --test air_range --test budget_width
cargo test --locked -p enclave-core --lib egress::tests
```

The AIR width and verifier-key digest changed intentionally. Existing v3 proofs
and approved keys must not be silently relabeled. The current relation is
`EpochAir-v5-full-span`; its full-limb span repair also changes the key domain.
See `docs/formal/slot-and-membership-refinement.md` for exact evidence boundaries. Production key/metadata
approval is separate from this source repair.
