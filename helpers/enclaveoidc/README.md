# Console-session OAuth broker — source contract

This executable supplies a fresh browser OAuth authorization-code/PKCE flow to
custody. It grants no custody authorization. UID703 independently verifies the
signed ID token, exact independently configured issuer/audience/subject, nonce,
signed authentication time and original ceremony scope, and requires separate
Touch ID and all inherited CTAP/UV/PRF/egress/quorum factors. Required organization
quorum remains unavailable without its separately reviewed provider.

`python3 helpers/enclaveoidc/build.py` compiles production source without
installing or starting authentication. `--native-test` builds a separate test
executable whose `--protocol-self-test` path is absent from production. The
packager signs `EnclaveOIDC.app` as `com.enterprise.enclave.oidc-broker` and includes
its exact code hash in protected pins. Production enforces the hardened runtime;
L3 production Team ID/entitlement qualification remains required.

An explicitly selected target appends `--deployment-target DESCRIPTOR` after
`--identity-config PATH --oauth-config PATH`. Both paths must exactly equal the
selected support root plus `oidc-broker-identity.json` and `oidc-oauth.json`.
The protected descriptor fixes the socket at
`socket_root/oidc/<actual current console uid>/broker.sock` and the sole pin
file. Identity JSON cannot select another socket, configuration or pin source.
Configured path spelling is preserved; only fixed Darwin root aliases are
normalized for held no-follow filesystem traversal. Descriptor raw bytes are
rechecked before configuration/peer use and around socket publication.

Selected mode requires the descriptor and optional packaged pin mode to match
the helper's compiled mode. Build with `--signing-mode local-pins` (the default)
or `--signing-mode team-id`; the latter adds `depot_TEAM_ID_MODE`. Selected
startup and peer checks require this helper's original signing identifier,
valid code, hardened runtime, matching Team ID mode and exact selected OIDC pin.
Custody remains UID703 plus its separate exact selected identifier/pin and
reciprocal Team ID checks. These source checks do not authenticate a deployment
instance against another unconfined process using the same UID and code.

The test build accepts only exact `--protocol-self-test` or
`--deployment-target-self-test` invocations and refuses production activation.
The latter exercises pure synthetic L2/L3 descriptor, raw-byte, argument,
configuration/socket, pin and compiled-mode checks. It performs no filesystem,
native session/code-signature observation, browser, IdP or credential operation.
Builds and pure fixtures do not provision the descriptor, OAuth/issuer authority,
root runtime directories or protected code pins and do not establish readiness.

The Aqua LaunchAgent runs once at login with KeepAlive=false. It requires these
already provisioned root-owned regular files and root-owned non-writable,
non-symlink ancestors, no hardlinks, and bounded size (16 KiB). Configuration is
public and contains no client secret or private signing key. Each file must be
exact compact sorted-key JSON, with no newline, using unescaped slashes; unknown
or duplicate members, alternative serialization and stale sessions refuse.

- `/Library/Application Support/EnterpriseEnclave/oidc-broker-identity.json`:
  exact keys `v=1`, `socket=/var/run/enclave/oidc/<actual uid>/broker.sock`,
  `identifier=com.enterprise.enclave.oidc-broker`, `console_uid`,
  `audit_session_id` and exclusive Unix-second `expires_unix`. Root must bind the
  actual current console UID and positive native audit session; guessed/default
  values cannot establish readiness. Logout/relogin invalidates the old record.
- `/Library/Application Support/EnterpriseEnclave/oidc-oauth.json`: exact keys
  `v=1`, `issuer`, `audience`, `client_id`, `authorization_endpoint`,
  `token_endpoint`, `redirect_uri`, `callback_scheme`, `expires_unix`. Endpoints
  require HTTPS, no userinfo/query/fragment, and default/443 port. The custom
  callback scheme starts with `com.enterprise.enclave.oidc`; redirect URI must
  have that exact scheme and a host, no query/fragment/userinfo/port. The public
  client, exact redirect and genuine fresh authentication policy must be
  independently registered with the organization's IdP.

The independent TUF/CAS authority target `custody-oidc-authority-v1.json` also
must be provisioned and authenticated; local OAuth configuration does not
supply its signing keys or expected principal. Only currently supported genuine
EdDSA ID tokens can be admitted. No credentials, fictitious authority, root
configuration, code pins or IdP enrollment are generated by this helper or its
build. Signed configuration renewal and root per-login provisioning remain
operational prerequisites; packaging a LaunchAgent does not implement them.

Root runtime maintenance prepares `oidc` mode0755 and per-console `<uid>`
mode2710, owned by console UID/group8703. The broker exclusively locks its own
nofollow file and serves a mode0660 socket. Reciprocal UID/code/team-or-pin and
current audit-session checks precede request bytes, browser start and reply.
The closed CBOR request has 11 fields, a nonce and full intent/boot binding, and
an unchanged complete original ceremony deadline no longer than 10 seconds.
Single-flight requests cannot renew this deadline. Ephemeral browser sessions,
state and S256 PKCE are mandatory; token HTTP redirects and ambient credentials
are refused. Duplicate JSON token response members and oversized streams refuse.

Observed lock/session resignation invalidates a main-queue admission generation
and closes active authentication; requests still decoding cannot resurrect it.
Cancellation, socket changes, config/session changes or the original deadline
close the operation. Final token write is bounded by the earlier of original
deadline and two seconds; partial/uncertain delivery never retries. A fresh
ceremony is required. Initial screen-lock state when this process launches,
native prompt presentation with the current anchor window, actual Foundation
cancellation timing and login/BTM transitions require genuine GUI qualification.
Notification handling alone is not proof of initial screen-lock readiness.

Owned byte arrays/token `Data` and reply buffers receive explicit wiping/reset
attempts; shutdown drops references and cancels browser/network operations.
Swift String copies of state, code, verifier and ID token; Foundation URL/body/
JSON/network buffers; allocator/kernel/socket queues; browser/IdP state and OS
copies remain separate memory owners. This source provides no physical erasure
claim for them. No token/code/verifier/PIN/PRF/private key is written to logs,
argv, environment or controller artifacts by this implementation.

Installed/privileged provisioning and genuine login are not part of build or
private selftest. In an authorized test deployment, provision the actual public
IdP/authority and current session records; verify exact pins and distinct
UID703/console audit identity; run fresh IdP -> separate Touch ID -> selected
CTAP/UV/PRF plus all inherited factors within the original cap. Test cancellation
at request-read/browser/token-read/final-write phases, lock/logout/relogin/fast
switch, expired/config/pin changes and signed-newnonce/old-auth-time rejection.
Collect source-bound non-secret outcomes and measurements. Preserve counters,
revocations and policy/generation floors when rolling code back; never revive an
outstanding token/lease. Installer/uninstaller must quiesce all loaded local GUI
instances before replacing or removing either app/shared pins, and refuse if an
old process remains. Mock filesystem tests establish ordering only.
